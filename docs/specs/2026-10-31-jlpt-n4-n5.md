# JLPT N4 / N5 courses

## Scope
Activate N4 and N5 on extension and Android using the two user supplied ZIPs.
N1 remains a coming-soon course. Preserve N2, N3, Kaiwa progress and application IDs.

## Data inspection
Both SQLite files pass integrity_check and foreign_key_check. The manifests explicitly
do not claim semantic approval. OCR merges vocabulary columns, corrupts grammar headings,
and can attach a translation to the wrong Japanese sentence. Exercise rows are whole pages
with no choices or verified keys. Do not grade those rows or import uncertain candidates.
Normalize and review playable content in a separate, reproducible editorial overlay, with
stable original IDs, source references, ZIP SHA-256, inclusion/exclusion audit and dictionary license.
Do not embed full textbooks, raw OCR, source binaries, audio URLs or temporary database files.
Curated examples must be labeled as editorial when authored, not as verbatim source quotations.

## Experience
Five chapters per new course, small vocabulary/kanji/grammar stages, chapter challenges and
one final challenge. Every ordinary stage is immediately selectable. Final challenge unlocks
only after all other stages are completed, regardless of score.
Reuse weak-card study transfer and existing per-course sync schema.
Use existing planned Kyoto sakura / snowy onsen motifs with responsive scenery and Raku mascot.
Translate every new UI label into English and Japanese; course content remains Japanese/Vietnamese.
Lazy-load each course; do not parse all databases at startup.

## Verification gates
Cloud tests: source checksums and audit consistency, stable IDs, nonempty quizzes for every stage,
four unique choices with exactly one answer, source/answer consistency, dictionary reading overlap
rejection, final gating, progress merge, notebook conversion, shared platform parity.
Real Chromium flows for extension + Android viewport: both course maps, a learned card, a wrong
answer, completion persistence, final lock, N1 placeholder, translated UI and no clipped controls.
Existing Node/browser suite and Android builds/device smoke tests remain required.
Inspect generated screenshots before merge. Merge only the tested tree into main.
